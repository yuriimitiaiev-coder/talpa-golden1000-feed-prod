# TALPA Golden1000 — production setup

## Поточна модель

Golden1000 = контрольований пул місткістю до 1000 SKU.
Старт: 950 ACTIVE, 0 налаштованих RESERVE, 50 вільних місць.

## Керування складом

Редагувати тільки `pool/catalog_pool_*.csv`.

- `ACTIVE` — SKU входить у `golden1000.xml`.
- `RESERVE` — SKU залишається затвердженим у керуючому пулі, але у XML не входить.
- Для нового SKU потрібно вказати постачальника та існуючий `prom_group_id`. `prom_offer_id` можна залишити порожнім — при першій збірці буде використано стабільний ID із фіда постачальника. `fallback_price` задається як контрольна остання ціна на випадок тимчасового зникнення SKU з джерела.

Перед видаленням/приховуванням старого товару у Prom спочатку переконатися, що новий SKU успішно створений/оновлений та загальна кількість товарів не перевищує ліміт.

## Автоматична збірка

Workflow запускається:
- одразу після зміни production-файлів у `main`;
- кожні 4 години;
- вручну через `workflow_dispatch`.

Постачальники:
- SIGMA: публічний XML;
- ZaInstrumentom: URL у GitHub Secret `ZAINSTRUMENTOM_FEED_URL`.

## Налаштування Prom

URL імпорту:
`https://yuriimitiaiev-coder.github.io/talpa-golden1000-feed-prod/golden1000.xml`

Для регулярного оновлення:
- Ціна — ON;
- Наявність — ON;
- Кількість — ON;
- Назва — OFF;
- Опис — OFF;
- Фото — OFF;
- Група — OFF;
- Характеристики — OFF;
- товари, яких немає у файлі — залишити без змін.

Перший запуск після переходу на нову архітектуру перевірити вручну на Prom до остаточного увімкнення періодичного імпорту.
