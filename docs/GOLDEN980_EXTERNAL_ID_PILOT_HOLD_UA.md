# TALPA Golden980 — критичне уточнення процедури зовнішнього ID

Дата: 01.11.2026. **Тільки підготовка, без дозволу на запуск імпорту.**

## Встановлені факти
- Товар `4003021` існує в Prom під внутрішнім `Унікальний_ідентифікатор=3257930946`.
- Станом на експорт `export-products-01-11-26_11-43-55.xlsx` його `Ідентифікатор_товару` порожній.
- Для всіх 123 нових SKU Golden980 ситуація така сама — потрібно зіставлення, а не створення нових товарів.
- Прапорець «Тільки оновлення» у фактичному інтерфейсі Prom приховує вибір конкретних полів. Не можна вимагати одночасної активації цього прапорця й вибору «Код товару/Артикул».
- «Код товару/Артикул» ≠ «Ідентифікатор_товару» ≠ «Унікальний_ідентифікатор».

## Знайдена процедура з цитатою підтримки Prom
У документації УкрСклад (переказ підтримки Prom) описано: експортувати товар XLSX із Prom, у `Ідентифікатор_товару` вписати зовнішній ID, зберегти незмінний `Унікальний_ідентифікатор`, імпортувати **з примусовим оновленням**; саме внутрішній ID використовується для знаходження картки.

Джерело: https://www.softbalance.com.ua/help/sklad_im_ua.html# (розділ «Особливості роботи з Prom.ua»).
Додаткове незалежне джерело: https://salesdrive.ua/blog/prom-external-id/ .

Зауваження: джерело описує попередню версію API/UI. Перед запуском реального імпорту підтвердити поведінку саме чинної конфігурації Prom, включно з наслідками для полів і можливістю примусового оновлення **однієї** картки.

## Оцінка попереднього тестового файлу
`TALPA_PROM_ID_PILOT_4003021_2026-11-01.xlsx` містить 10 колонок, включаючи назви, описи, службовий ID та новий зовнішній ID, але це не повний експорт із Prom (в експорті 129+ колонок й окрема вкладка груп). Файл **не визнано безпечним для тестового примусового імпорту без додаткової перевірки**. При спробі змінити лише артикул це не доводить запису зовнішнього ID.

## Безпечний наступний крок
1. Підготувати тестовий XLSX **із оригінального експортного рядка Prom** (без ручного переписування інших полів), змінюючи винятково `Ідентифікатор_товару` у SKU `4003021`.
2. Встановити, як Prom у цьому режимі обробляє незазначені або наявні комерційні поля; не допустити зміни ціни, кількості, наявності й фото.
3. Лише після підтвердження механізму та дозволу власника виконати контрольний імпорт 1 SKU.
4. Отримати **свіжий** експорт і перевірити: рівно 980 SKU, один `4003021`, незмінний `Унікальний_ідентифікатор=3257930946`, правильний `Ідентифікатор_товару`, ціна/кількість/інші поля без побічних змін.
5. Тільки після PASS розглядати пакет для решти 122 SKU.
